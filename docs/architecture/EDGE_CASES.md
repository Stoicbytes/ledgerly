# Edge cases and failure states

How the dashboard and the public portfolio behave when things go wrong, from the October 2026
audit ([report](AUDIT_2026-10.md)). **Status:** Handled (how), **Fixed** (changed in the audit),
**Risk** (known and accepted for now), N/A (does not apply to this app).

## Sign-in and access

| Scenario                                   | Current behaviour                                                                                      | Status                                                                                | Test coverage                                |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- | -------------------------------------------- |
| Opening `/dashboard/...` signed out        | Redirect to sign-in, then back to the same page (only app paths are allowed as the return address)     | Handled                                                                               | `authScreens.test`, `redirects.test`         |
| Session expires or is revoked elsewhere    | Auth reports signed out → sync stops first, stores are cleared, sign-in shown                          | Handled                                                                               | `sessionProvider.test`                       |
| Password correct, two-step code still owed | Treated as not signed in until the code is entered; the database refuses data without it (aal2 policy) | Handled                                                                               | `verifyCode.test`, database tests (local)    |
| Refreshing the page                        | Session restored from browser storage (session-only unless "keep me signed in"); data reloaded         | Handled                                                                               | `authStorage.test`                           |
| Reading or changing another user's rows    | Impossible: Row Level Security, `user_id` fixed to the caller, composite foreign keys                  | Handled (database)                                                                    | Database tests (local, kept out of the repo) |
| A sign-up attempt by a stranger            | Refused by the allowlist hook                                                                          | Handled (database)                                                                    | Database tests (local)                       |
| Idle for the chosen time                   | Warning, then pending changes are sent and the user is signed out                                      | Handled; **Risk**: if offline at that moment, unsent changes are lost (no one to ask) | `idle.test`                                  |

## Saving and the network

| Scenario                                                                | Current behaviour                                                                                                                                                      | Status               | Test coverage                     |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | --------------------------------- |
| Supabase down when the dashboard opens                                  | "Your data could not be loaded" with **Try again**; nothing is shown as if it were yours                                                                               | Handled              | `cloudSync.test`                  |
| Offline while editing                                                   | Edits stay on screen; badge shows "Offline · will retry"; retried with back-off up to every 30 s until it works                                                        | Handled              | `cloudSync.test`                  |
| A request hangs                                                         | Abandoned after 30 s (price update: 150 s) and retried like an offline failure                                                                                         | **Fixed**            | `rpc.test`                        |
| The save reached the server but the reply was lost                      | The retry sends the same rows again; `sync_ledger` upserts by id, so nothing is duplicated                                                                             | Handled              | Database design                   |
| The database refuses a change (a rule is broken)                        | Data is reloaded from the database and a "change was refused" note is shown; **other unsaved edits made in the same moment are reloaded away too**                     | Handled; Risk (rare) | `cloudSync.test`                  |
| Closing or reloading the tab right after an edit                        | The change is sent as soon as the tab is hidden; leaving with something still unsent asks first                                                                        | **Fixed**            | `unsavedChanges.test`             |
| Signing out while offline with unsent changes                           | Asks: stay signed in (they are sent when back online) or sign out and lose them                                                                                        | **Fixed**            | `accountCard.test`                |
| Double tap on **Save** in the entry sheet                               | One entry (a second Save while the sheet closes is ignored)                                                                                                            | **Fixed**            | `transactionForm.test`            |
| Double tap on Save in other sheets (funds, trades, accounts, portfolio) | Those sheets are removed on the first save rather than animated away, so a second tap has nothing to press; the portfolio sheet disables Save while saving             | Handled              | Sheet tests                       |
| Adding a fund (AMFI) or share (ISIN), or importing a tradebook          | Prices for the new holding are loaded right after it is saved                                                                                                          | **Fixed**            | `cloudSync.test`                  |
| "Update prices" twice quickly                                           | The button is disabled while updating; the server skips a run within 30 minutes of the last one and the app says prices are up to date or an update is already running | Handled              | `store.test`, Deno function tests |
| Leaving a screen before a request finishes                              | Stores are app-wide, so the result still lands; results for a signed-out session are dropped (generation check)                                                        | Handled              | `cloudSync.test`                  |

## Two devices and stale data

| Scenario                                                                  | Current behaviour                                                                                                                                  | Status                     |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| Editing on phone and laptop at the same time                              | Each device sends its own changes; for the same row the last save wins                                                                             | **Risk** (one owner; rare) |
| A row deleted on one device, then edited on another that has not reloaded | The edit re-creates the row (upsert by id)                                                                                                         | **Risk**                   |
| Changes made on another device                                            | Shown when you come back to the app (tab shown again, phone app brought to the front), at most once a minute; no live updates while you look at it | **Fixed** (`refresh.test`) |
| Coming back with an edit not saved yet                                    | No reload: the edit is sent first; the next return picks up the rest                                                                               | Handled (`refresh.test`)   |
| An edit made while the reload is on its way                               | The edit wins: the reloaded data is dropped and the edit is saved                                                                                  | Handled (`refresh.test`)   |
| New contact messages while Portfolio is open                              | Shown after the next reload of the dashboard                                                                                                       | Risk (minor)               |

## Receipt photos

| Scenario                                         | Current behaviour                                                                                                                                                                               | Status             | Test coverage                      |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | ---------------------------------- |
| Photo picked while signed in                     | Uploaded at once to the private bucket; **Save** waits until the upload ends                                                                                                                    | Handled            | `PhotoField.test`, `receipts.test` |
| Upload fails (offline, migration 0011 not run)   | "Could not upload the photo…"; nothing is attached and the entry can still be saved                                                                                                             | Handled            | `PhotoField.test`                  |
| Sheet closed or reopened while uploading         | The finished upload is not attached to the new form; the file is tidied later                                                                                                                   | Handled            | `PhotoField.test`                  |
| Photo replaced or removed, entry deleted         | The old file stays until a later sign-in deletes unused files over a day old                                                                                                                    | Handled            | `receipts.test`                    |
| Another account's file path sent to the database | Refused (`valid_receipt`: the path must be in the row owner's folder); Storage refuses other folders too                                                                                        | Handled (database) | Database tests (local)             |
| Opening a receipt                                | A link valid for one minute, made when the photo is shown; nobody else can read the bucket                                                                                                      | Handled            | `storageRepository.test`           |
| Location data inside the photo                   | Web: removed by re-encoding before upload (HEIC that the browser cannot draw is uploaded as it is). Phones: the picker re-compresses and is asked for no location data; not verified on devices | Partial            | Not covered by tests               |

## Forms, input and display

| Scenario                                                                                                      | Current behaviour                                                                                                                                                                        | Status                                                  |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Invalid or missing fields                                                                                     | Messages next to the field and focus on the first problem; the database checks again                                                                                                     | Handled                                                 |
| Very long text, huge numbers                                                                                  | Most inputs have length limits; the database bounds amounts (up to ₹1,00,00,00,000 in paise) and text lengths                                                                            | Handled                                                 |
| Deleting an expense a repayment was "for"                                                                     | The repayment keeps its amount and is treated as a general payment; **Undo** links it again (before, a later edit of that repayment was refused by the database and lost)                | **Fixed** (`expenseStore.test`)                         |
| Opening balance, budget or date beyond what the database keeps                                                | Refused in the form (amounts up to ₹100 crore, dates 1900–2100); before, the save was refused and edits made at the same moment were reloaded away                                       | **Fixed** (`validation.test`)                           |
| Deleting an account, category or person and adding one with the same name before the change is sent (offline) | The database checks the new name before removing the old row, refuses the batch, and the app reloads                                                                                     | Risk (rare; wait for "Saved" before re-adding)          |
| A sum in the amount ("120+45")                                                                                | Worked out exactly to the paisa and shown underneath; an unfinished sum ("120+") is refused with a message; nothing is ever run as code                                                  | Handled (`calculator.test`)                             |
| A recurring date on the 31st (or 29 February)                                                                 | Shorter months use their last day; the next month goes back to the 31st                                                                                                                  | Handled (`recurring.test`)                              |
| A recurring entry whose category or account was deleted                                                       | **Add all** leaves it for you; **Add** opens the sheet to choose a new one; the account cannot be deleted while a recurring entry uses it                                                | Handled (`recurringActions.test`)                       |
| The app is not opened for months                                                                              | Every missed date is listed (up to 12 per entry at a time) to add or skip; nothing is added on its own                                                                                   | Handled                                                 |
| A due entry added on two devices                                                                              | Each device adds it (the next date moves on when the other device reloads)                                                                                                               | Risk (rare; one owner)                                  |
| A note starting with = + - @ in an export                                                                     | Saved with a leading apostrophe so Excel or Sheets cannot run it as a formula                                                                                                            | Handled (`csv.test`)                                    |
| Sale of more units or shares than held                                                                        | Refused by the form and again by the database (`check_fund_units`, `check_stock_quantity`)                                                                                               | Handled                                                 |
| Fund dates, amounts and stamp duty beyond what the database keeps                                             | Refused in the form (dates 1990–2100, amounts up to ₹100 crore, stamp duty up to ₹10 lakh, SIPs up to ₹10 crore); before, the save was refused and other edits were reloaded away        | **Fixed** (`forms.test`)                                |
| Share trades, dividends and manual prices beyond what the database keeps                                      | Refused in the form (dates 1990–2100, up to 100 crore shares, prices, charges and dividends up to ₹100 crore); before, the save was refused and other edits were reloaded away           | **Fixed** (`forms.test`)                                |
| A tradebook with a share whose ISIN changed (split or face-value change)                                      | One holding under the newest ISIN, joined to the share already in the app (before, a second share with the same symbol was added, the database refused the save and the import was lost) | **Fixed** (`importSplit.test`)                          |
| Shares vs index: a trade older than the index fund's NAV history (or in a gap of it)                          | No comparison; the sheet gives both dates and offers **Update prices** to fetch older NAVs, or another fund                                                                              | Handled (`benchmark.test`)                              |
| Shares vs index: a sale bigger than the index holding                                                         | The index holding counts as zero from then on, and the sheet says so                                                                                                                     | Handled (`benchmark.test`)                              |
| Import: a trade typed by hand or edited with a different price, or one order split into fills in the file     | Shown as **Possible duplicate**, unticked; the user ticks it to add it (before, it was added again)                                                                                      | **Fixed** (`importDuplicates.test`, `importSheet.test`) |
| Import: unticking a purchase a later sale needs                                                               | The holding warns and **Approve** is disabled until it is fixed                                                                                                                          | Handled (`importSheet.test`)                            |
| A fund or share held for a few weeks                                                                          | XIRR is shown only after a year (before, a 20 % gain in two months read as over 100 % a year); the gain on cost is shown instead                                                         | **Fixed** (`portfolio.test`)                            |
| SIP instalments brought in by a tradebook import                                                              | Count as recorded (before, every imported instalment was listed again with **Record**, inviting duplicates)                                                                              | **Fixed** (`sips.test`)                                 |
| A redemption spanning several purchases                                                                       | Split over the purchases it used (first in, first out), each with its own holding period and tax type                                                                                    | Handled (`capitalGains.test`)                           |
| Hybrid, index or other funds in the capital gains report                                                      | Listed **to check**: their tax depends on the fund's share of Indian equity, which the app does not know                                                                                 | Handled (by design)                                     |
| A goal deleted while funds are tied to it                                                                     | The funds are untied (as in the database); **Undo** ties them again                                                                                                                      | Handled (`insights.test`)                               |
| A fund saved from a form that does not show the expense ratio or goal                                         | Both are kept                                                                                                                                                                            | Handled (`insights.test`)                               |
| Notes: opening a note and closing it without changes                                                          | Keeps its place (notes are ordered by last edit) and saves nothing                                                                                                                       | **Fixed** (`NotesScreen.test`)                          |
| Notes: a note emptied out and closed                                                                          | Deleted, with **Undo** (before, an empty note was kept)                                                                                                                                  | **Fixed** (`NotesScreen.test`)                          |
| Notes: text ⇄ checklist beyond the limits (200 items, 20,000 characters)                                      | Refused with a message (before, the extra lines or text were dropped silently); blank list items are not saved                                                                           | **Fixed** (`notes.test`)                                |
| Notes: Undo after archiving a pinned note                                                                     | The note comes back pinned                                                                                                                                                               | **Fixed**                                               |
| Notes: the label being viewed is removed from its last note                                                   | The view returns to all notes (before, it stayed on an empty, invisible label)                                                                                                           | **Fixed** (`NotesScreen.test`)                          |
| Notes: the same label typed in another case                                                                   | Uses the spelling already in use, so one label shows once                                                                                                                                | **Fixed** (`notes.test`)                                |
| Notes: deleted by mistake days ago                                                                            | In **Recently deleted** for 7 days (restore or delete for good); removed for good when the app next loads after that                                                                     | Handled (`NotesScreen.test`, `notes.test`)              |
| Notes: a reminder that is due                                                                                 | Red on the card, under **Reminders**, and in **Reminders due** on Overview until **Done** or a new date; no push notifications                                                           | Handled (`RemindersCard.test`)                          |
| Notes: database without migration 0015                                                                        | Reminders and Recently deleted are hidden; delete removes at once (with Undo)                                                                                                            | Handled (`NotesScreen.test`, `noteRows.test`)           |
| Empty data (new account)                                                                                      | Empty states with a next step (for example **Add starter categories**)                                                                                                                   | Handled                                                 |
| Dates and time zones                                                                                          | Dates are calendar dates (no time); "today" is the device's date                                                                                                                         | Handled                                                 |
| Rupee formatting                                                                                              | Indian grouping (lakhs, crores) everywhere amounts are shown                                                                                                                             | Handled                                                 |
| Phones and small screens                                                                                      | Layouts adapt; sheets become bottom sheets; checked at 390 px wide                                                                                                                       | Handled                                                 |
| Phone menu on the public site (Safari)                                                                        | Covers the page (the header's blur moved to a background layer)                                                                                                                          | **Fixed** (PR #21)                                      |
| Keyboard use                                                                                                  | Sheets are dialogs with focus kept inside and Escape to close                                                                                                                            | Handled                                                 |

## Public portfolio

| Scenario                                | Current behaviour                                                                                    | Status                                          |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| Nothing published yet                   | "Nothing is published here yet" (404) with a Dashboard button                                        | Handled                                         |
| Database unreachable                    | 503 page; the browser retries                                                                        | Handled                                         |
| Unknown project address                 | 404 page                                                                                             | Handled                                         |
| Expired preview link                    | "This preview link has expired"                                                                      | Handled                                         |
| Contact form spam                       | Hidden field and minimum fill time (silently dropped), at most 3 links, per-network and daily limits | Handled; limits slow abuse, they cannot stop it |
| Contact form sent twice                 | The button is disabled while sending                                                                 | Handled                                         |
| A secret key put in the site's settings | The server refuses to use it and answers 500                                                         | Handled                                         |
